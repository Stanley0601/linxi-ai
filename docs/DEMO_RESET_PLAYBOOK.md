# LifeScript Demo Reset Playbook

面向本地录屏、彩排、答辩前的演示状态恢复手册。

## 适用场景

当项目本身已经可以正常 `build` / `lint`，但你担心浏览器里残留的本地状态影响现场展示时，优先参考这份手册。

典型场景包括：

- 上次演示留下了搜索词、草稿或筛选条件
- 快捷视图、固定聊天、静音聊天的状态与本次讲解路径不一致
- 想尽量保留已有演示记忆，但又不希望现场页面“看起来怪怪的”
- 需要在不改代码的前提下，快速把演示路径恢复到可控状态

---

## 1. 先判断：这是 Bug，还是本地状态还原

在 LifeScript 里，部分页面行为本来就会被本地持久化，以便：

- 下次录屏更快恢复现场
- 快速继续上次演示路径
- 保留搜索、筛选、聊天、动态互动等上下文

因此看到“和默认初始状态不一样”的页面表现时，先不要急着认定为故障。

建议先问自己三个问题：

1. 页面还能否正常点击与切换？
2. 当前表现是否可能由上次演示遗留状态导致？
3. 我现在需要的是“恢复可讲述路径”，还是“彻底回到初始空白状态”？

如果页面仍可操作，大多数情况下优先做“恢复可讲述路径”，而不是直接大清空。

---

## 2. 最推荐的低风险恢复顺序

如果现场只剩 1~2 分钟准备时间，按下面顺序处理最稳妥：

### A. 回到消息列表主视图

先确认自己回到了最容易重新组织演示的入口：

- 消息列表
- 默认主视图
- 没有误停留在深层聊天页、资料页或结局页

### B. 清空显性筛选条件

优先处理会直接影响讲解路径的状态：

- 清空搜索词
- 关闭快捷筛选
- 切回默认列表模式
- 取消只看某一类聊天的局部视图

### C. 检查“继续上次演示”入口是否可用

如果“继续上次演示”本身就是你要讲的亮点，可以保留；如果它让路径变复杂，就优先从普通消息列表进入。

### D. 选择一个最稳的角色重新起讲

建议只挑一个当前最容易讲清楚的角色，重新走主线：

1. 打开消息列表
2. 进入该角色聊天页
3. 展示建议回复 / 关系推进
4. 再转动态页或资料页

这样能最快把现场拉回到一条完整叙事线上。

---

## 3. 如果只是“局部脏”，不要直接清空全部状态

以下情况通常属于“局部脏”：

- 搜索词没清
- 还停留在某个快捷视图里
- 某条草稿没发
- 刚好有几个已固定或已静音聊天影响排序

这时更建议：

- 手动把搜索词清空
- 退出当前筛选
- 回到主列表重新选择角色
- 只调整会影响讲解的那一项状态

不建议一上来就重置全部本地状态，因为：

- 你可能会丢掉本来可以拿来讲的演示素材
- “继续上次演示”之类的亮点会一起消失
- 现场需要重新组织路径，反而更慢

---

## 4. 什么情况下才建议彻底重置本地状态

只有在以下情况之一出现时，才建议考虑彻底清理浏览器本地状态：

- 页面虽然能打开，但演示路径已经混乱到难以恢复
- 多个列表排序、筛选、草稿、会话恢复状态叠加，几乎无法判断当前场景
- 你准备录一段“更像首次体验”的演示，需要尽量接近初始状态
- 你明确知道当前本地数据已经不适合再拿来讲故事

---

## 5. 彻底重置前的更稳妥替代方案

在真正清空前，优先尝试下面两种更温和的方法：

### 方案 A：开一个新的浏览器无痕窗口

适合：

- 想快速验证“接近新用户”的展示效果
- 不想破坏当前浏览器里已经积累的本地状态

优点：

- 风险低
- 退出后不会影响原来的演示环境
- 最适合彩排和对比演示路径

### 方案 B：换一个新的浏览器 Profile 或独立窗口环境

适合：

- 需要多次录不同版本的演示
- 想保留“旧演示现场”和“新演示现场”两套状态

优点：

- 更容易复用
- 不用频繁清缓存
- 对录屏和答辩准备更友好

---

## 6. 如果确定要清空，只清 localhost 对应站点的数据

如果最终确实需要重置，建议只清理本地演示站点对应的数据，而不是全浏览器大扫除。

推荐原则：

- 只处理当前本地地址对应的站点数据
- 不影响其他网站登录态和缓存
- 清空前确认当前演示素材是否还需要保留

执行后，建议立即重新打开本地项目并快速检查：

- 首页是否能正常进入
- 消息列表是否可用
- 聊天页是否能正常展示
- 动态页与资料页是否还在主链路可达范围内

---

## 7. 演示前 30 秒快速确认清单

如果已经完成恢复，最后用这份极简清单做一次确认：

- [ ] 当前在正确分支
- [ ] `npm run lint` 已通过
- [ ] `npm run build` 已通过
- [ ] 本地页面可打开
- [ ] 消息列表处于可讲述状态
- [ ] 搜索词与筛选条件符合本次讲解路径
- [ ] 已确认要先展示哪个角色
- [ ] 已准备一条最短主链路：消息列表 → 聊天页 → 动态页 / 资料页

---

## 8. 推荐的最短救场话术

如果现场状态还是和预期略有差异，可以直接这样解释：

> LifeScript 会保留本地关系和演示上下文，所以你现在看到的不是死板的初始页，而是一个被用户长期互动过的 AI 好友现场。

这句话通常能把“状态残留”转换成“产品记忆感”的正向表达。

## 10. 结论

当 `build` 与 `lint` 已经通过，但你担心现场页面“不够干净”时，最稳妥的做法通常不是急着改代码，而是：

1. 先识别是否只是本地状态残留
2. 优先恢复可讲述路径
3. 必要时再做局部清理
4. 只有在状态彻底失控时才清空站点数据

这样更符合比赛冲刺期“小步、可控、可解释”的演示准备策略。
