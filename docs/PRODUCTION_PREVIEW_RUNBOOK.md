# LifeScript Production Preview Runbook

面向本地生产模式预演、提交流程前复验，以及录屏前确认“真实构建产物是否仍可讲述”的快速操作手册。

当 `npm run build` 与 `npm run lint` 已通过，但你还想进一步确认“不是开发态巧合可用，而是生产构建后也能稳定打开、稳定讲述”时，优先使用这份文档。

## 适用场景

- 准备在本地用生产模式做最后一轮预演
- 想确认 `next build` 产物在 `next start` 下仍可正常访问
- 准备录屏、答辩或交付前，希望补一轮更接近真实部署形态的验证
- 当前工作区已较脏，不适合继续扩大代码改动，但仍想做一项低风险、可复用的工程补强

---

## 1. 先做固定检查

先执行：

```bash
git status --short --branch
git branch --show-current
npm run build
npm run lint
```

建议先确认：

- 当前仍在目标分支，例如 `feat/v12-unified-baseline`
- `build` 与 `lint` 已通过
- 当前工作区虽然可能较脏，但本轮目标只是做生产模式预演，不继续扩大核心代码修改范围

如果 `build` 或 `lint` 尚未通过，先不要进入生产模式预演。

---

## 2. 为什么还要做生产模式预演

开发环境可用，并不完全等于生产构建也没有问题。

生产模式预演主要回答三个问题：

1. **真实构建产物能否启动**
2. **核心演示链路在生产模式下是否仍可讲述**
3. **录屏或答辩前是否存在只会在生产模式暴露的问题**

尤其在比赛冲刺阶段，如果你已经不准备继续做高风险改动，那么补一轮生产模式预演，往往比再多改一点代码更稳妥。

---

## 3. 推荐的本地生产预演命令

### 构建

```bash
npm run build
```

### 启动生产模式

默认端口可直接使用：

```bash
npm run start
```

如果你希望避开本地其他服务，建议显式指定端口，例如：

```bash
npm run start -- --port 3010
```

默认访问示例：

```text
http://localhost:3010
```

如果你没有指定端口，则按终端实际输出地址访问。

---

## 4. 推荐预演顺序（3~5 分钟）

建议按下面顺序快速确认：

### A. 首页 / 落地页

确认：

- 页面可正常打开
- 没有明显白屏或首屏阻断
- 基础样式与布局正常

### B. 消息列表

确认：

- 列表正常渲染
- 搜索框可输入
- 快捷视图可切换
- “继续上次演示”相关入口仍可讲述

### C. 聊天页

确认：

- 能进入至少一个角色会话
- 消息气泡正常渲染
- 建议回复、输入区、草稿提示等反馈正常

### D. 动态页 / 空间流

确认：

- 动态列表正常渲染
- 筛选可切换
- “恢复默认”或等价入口可用

### E. 资料页 / 我的页 / 结局页

确认：

- 关键摘要区域仍可见
- 页面结构完整
- 可作为演示收束页使用

---

## 5. 最小生产模式验收表

只做最小确认时，可逐项过一遍：

- [ ] `npm run build` 已通过
- [ ] `npm run lint` 已通过
- [ ] `npm run start` 或 `npm run start -- --port 3010` 已成功启动
- [ ] 本地浏览器可以正常打开生产模式页面
- [ ] 首页、消息列表、聊天页至少各验证过一次
- [ ] 动态页或资料页至少验证过一个收束页面
- [ ] 没有出现明显白屏、严重报错或主链路阻断
- [ ] 当前版本仍然适合录屏、答辩或继续作为交付基线

---

## 6. 如果生产模式和开发模式表现不一致

优先按以下顺序排查：

1. 先重新确认 `npm run build` 是否刚刚通过
2. 再确认是否使用了正确端口访问
3. 查看浏览器控制台是否有明显报错
4. 回到 `docs/SMOKE_TEST_MATRIX.md` 按主链路重新做最小验证
5. 如问题只在生产模式出现，先记录现象，不要顺手扩大成结构性重构

处理原则：

- 优先修复首个明确阻断问题
- 不要同时展开多个方向的优化
- 如果修复需要改动主状态机、共享类型或恢复逻辑，先暂停并重新评估

---

## 7. 常见场景建议

### 场景 A：只是想确认当前版本适不适合录屏

最推荐顺序：

```text
build → lint → start(3010) → 打开首页 → 走一遍消息列表 → 进入聊天页 → 选一个收束页
```

### 场景 B：工作区已经很脏，不想再扩大改动

最推荐动作：

- 不继续碰核心业务文件
- 做一次生产模式预演
- 把结论补到迭代日志或通知里

### 场景 C：准备发 PR 或整理 patch

最推荐动作：

- 先跑 `npm run verify`
- 再做一轮生产模式预演
- 最后整理本轮改动范围、验证结果与风险边界

## 10. 一句话原则

在 LifeScript 当前阶段，生产模式预演的价值不在于增加更多改动，而在于用接近真实交付形态的方式，再确认一次当前版本仍然可打开、可讲述、可复验。
