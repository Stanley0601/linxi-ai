# LifeScript Iteration Log

用于记录每一轮低风险自动迭代的固定检查项、改动摘要与交付边界，帮助后续自检、录屏准备与协作说明。

## 使用目的

在比赛冲刺期，工作区经常会同时存在多类未提交变更。相比把信息散落在聊天记录里，这份日志更适合沉淀每轮自动迭代的：

- 起始检查结果
- 改动类型与风险等级
- 验证结论
- 对后续协作者有帮助的备注

它不替代详细设计文档，而是作为“本轮做了什么、为什么这样做、是否已经验证”的轻量记录。

## 建议记录格式

每次自动迭代可按以下结构追加一条记录：

```markdown
## YYYY-MM-DD HH:mm
- 分支：
- Git 状态概览：
- 本轮目标：
- 改动类型：工程问题修复 / 体验优化 / 小功能增强 / 轻度重构 / 文档完善
- 具体改动：
- 验证结果：build / lint / typecheck
- 风险说明：
- 后续建议：
```

## 风险分级建议

### 低风险

适合直接执行并记录：

- 文档补充
- 文案与空态提示优化
- 无障碍增强
- 已有能力的展示增强
- 不改数据结构的小型体验优化

### 中风险

记录前应说明影响面，并确保已验证：

- 公共类型新增字段
- 本地持久化行为调整
- 影响多个页面的展示逻辑修改
- 搜索 / 筛选 / 排序规则变化

### 高风险

默认不应在自动迭代中直接执行，除非明确得到人工确认：

- 主状态机重写
- 核心数据模型重构
- 大规模文件迁移
- 修改历史提交、强推、批量覆盖现有改动

## 推荐配合命令

```bash
git status --short --branch
git branch --show-current
npm run lint
npm run build
npm run verify
```
