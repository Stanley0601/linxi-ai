# LifeScript Production Preview Checklist

面向本地生产模式预演前后的极简核对卡，帮助在 `build` / `lint` 已通过后，用最短路径再次确认“真实构建产物是否仍适合录屏、答辩与交付”。

它适合与 `docs/PRODUCTION_PREVIEW_RUNBOOK.md` 配合使用：
- 这份清单负责 **快速核对**
- `Runbook` 负责 **完整步骤与排查说明**

## 适用场景

- 准备在本地启动 `next start` 做最后一轮预演
- 距离录屏、答辩或提交只剩几分钟，想做一次极简复验
- 当前工作区已经较脏，不适合继续扩大战线，但仍想做一个低风险的工程增强
- 希望把“生产模式是否还可讲述”从口头判断变成固定清单

---

## 1. 开始前 30 秒检查

先确认以下 4 件事：

- [ ] 当前仍在目标分支（例如 `feat/v12-unified-baseline`）
- [ ] 已看过 `git status --short --branch`，知道工作区是否较脏
- [ ] `npm run build` 已通过
- [ ] `npm run lint` 已通过

如果上面任一项不满足，先不要进入生产模式预演。

---

## 2. 推荐命令卡

### 构建

```bash
npm run build
```

### 启动生产模式

```bash
npm run start -- --port 3010
```

### 访问地址

```text
http://localhost:3010
```

如果 3010 已被占用，可以换别的端口；但建议在记录里明确写出本轮实际使用的端口。

---

## 3. 3 分钟最小预演顺序

建议严格按这个顺序走，避免来回跳页：

1. **首页 / 落地页**：确认能正常打开，没有白屏
2. **消息列表**：确认列表、搜索框、快捷视图仍可讲述
3. **聊天页**：任选一个角色进入，确认消息气泡与输入区正常
4. **动态页**：确认列表能渲染，筛选与恢复默认入口仍可用
5. **资料页 / 我的页 / 结局页**：任选一个收束页，确认可用于讲解结尾

如果时间只够 1 分钟，至少完成：

```text
首页 → 消息列表 → 聊天页 → 一个收束页
```

---

## 4. 最小通过标准

满足以下条件即可认为“本轮生产模式预演通过”：

- [ ] 生产模式成功启动
- [ ] 浏览器可正常访问页面
- [ ] 没有出现白屏或主链路阻断
- [ ] 至少验证过消息列表与聊天页
- [ ] 至少验证过一个收束页（动态 / 资料 / 我的 / 结局）
- [ ] 当前版本仍适合录屏、答辩或继续作为提交基线

---

## 5. 如果失败，先这样处理

如果生产模式预演未通过，先按这个顺序处理：

1. 先记录首个明确现象
2. 只定位一个最主要阻断点
3. 回看 `build` / `lint` 是否确实刚刚通过
4. 用 `docs/SMOKE_TEST_MATRIX.md` 补做最小主链路复验
5. 如果修复会触碰主状态机、共享类型或大范围页面联动，先停下说明，不继续扩大改动

不建议的做法：

- 一边排查一边顺手重构
- 同时改多个页面
- 在没有明确阻断点时扩散修改范围

---

## 6. 结果记录模板

可直接复制到 `docs/ITERATION_LOG.md`、通知消息或个人备注：

```markdown
- 生产模式预演：通过 / 未通过
- 启动命令：npm run start -- --port 3010
- 访问地址：http://localhost:3010
- 预演范围：首页 / 消息列表 / 聊天页 / 动态页 / 收束页
- 阻断问题：无 / 有（简述）
- 当前结论：适合录屏答辩 / 仅适合开发调试 / 需要暂停继续评估
```

---

## 7. 与其他文档的配合关系

- `docs/PRODUCTION_PREVIEW_RUNBOOK.md`：完整生产模式预演步骤
- `docs/SMOKE_TEST_MATRIX.md`：最小冒烟路径与失败分级
- `docs/FINAL_SUBMISSION_CHECKLIST.md`：提交与最终交付前的总核对
- `docs/ITERATION_WRAPUP_CARD.md`：每轮结束后的记录、通知与停手判断

---

## 8. 一句话原则

当 LifeScript 当前工作区已经较脏、`build` 与 `lint` 又都通过时，最稳妥的下一步通常不是继续碰核心代码，而是用一张短清单快速确认：生产模式下，这个版本仍然能被打开、被讲清、被交付。
