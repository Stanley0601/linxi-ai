# LifeScript Feature Value Map

用于把“功能点、用户价值、演示证据、工程证据、推荐说法”放到同一张速查表里，方便在比赛冲刺期快速统一讲法。

当 `npm run build` 与 `npm run lint` 已通过、但工作区较脏、不适合继续扩大核心业务代码改动时，这类独立文档是更稳妥、收益也很高的自动迭代交付物。

## 适用场景

- 比赛演示前，想快速确认“每个页面到底证明了什么价值”
- 答辩时，被追问“这个功能除了好看还有什么意义”
- 录屏配音时，想避免只描述界面而没有讲清产品价值
- 协作者接手讲解时，需要统一从“功能”转成“价值”的表达方式

---

## 1. 一句话使用方法

如果时间很短，针对每个功能点至少补齐这 4 件事：

1. **它是什么**：界面上看到了什么
2. **它解决什么**：为什么用户会在意
3. **它如何被证明**：当前 Demo 里如何被展示
4. **它为什么可信**：工程上有什么状态、数据或链路支撑

可直接套这个句式：

> 这个功能不是单纯为了展示页面元素，而是为了证明用户和 AI 之间的关系会被持续记录、持续反馈、持续推进。

| 动态 / 空间流 | 让 AI 看起来不是只在聊天框里存在，而是真的在生活 | 动态页里能看到与状态、兴趣、关系有关的内容与互动 | 动态数据、筛选偏好、本地记忆与展示排序已串联 | “聊天之外，它还在持续暴露自己的生活状态。” |
| 搜索与快捷视图 | 让演示、恢复和高频场景切换更高效 | 搜索词、快捷视图、固定聊天、静音聊天等都可直接操作 | 搜索状态、筛选状态、本地持久化与排序逻辑可复验 | “它提升的不只是操作效率，也提升了演示路径的稳定性。” |
| 继续上次演示 / 恢复入口 | 让答辩、录屏或多轮彩排能快速回到可讲述节点 | “继续上次演示”入口会指向最近可恢复的角色与聊天 | 最近会话恢复逻辑、本地缓存与页面入口已形成闭环 | “它不是为了偷懒，而是为了让现场恢复路径更可控。” |
| 资料页关系状态 | 让关系变化不只存在于文案，而有明确可解释的外显反馈 | 资料页能看到角色信息、关系状态与摘要提示 | 角色基础信息、关系字段、状态映射与展示组件已就位 | “用户可以看到这段关系处于什么阶段，而不是只能靠感觉猜。” |
| 结局与时间线 | 让用户感知自己真的影响了 AI 的人生走向 | 结局页、时间线与指标总结卡可以用来收束讲述 | 剧情阶段、结局数据、时间线视图与页面流转已存在 | “这证明它不是一次性聊天，而是会被你改变的人生轨迹。” |
| Mock / 真实模型双模式 | 让项目既能稳定演示，也具备继续升级的空间 | 没有密钥时仍可完整展示主流程；有密钥时可接真实模型 | `/api/chat` 已预留接口，Mock 与真实模式并存 | “我们优先保证体验链路稳定，同时保留模型升级接口。” |

## 3. 三种最常用的讲法模板

### 模板 A：偏产品价值

> 这个功能的重点不是“多一个页面元素”，而是让用户感到这个 AI 真的在持续生活，并且会对关系变化做出反馈。

适合场景：

- 讲主动消息
- 讲动态页
- 讲关系阶段

### 模板 B：偏演示稳定性

> 这个功能除了提升体验，也在帮助我们把比赛现场、录屏和答辩路径控制得更稳定、更容易恢复。

适合场景：

- 讲继续上次演示
- 讲搜索与快捷视图
- 讲本地状态持久化

### 模板 C：偏工程完成度

> 它不是只停留在概念说明，而是已经接入了现有状态、页面流转和验证链路，所以我们可以稳定地演示、复验和继续迭代。

适合场景：

- 讲聊天接口
- 讲持久化状态
- 讲 CI / build / lint

## 4. 页面级推荐价值表达

## 消息列表页

优先强调：

- AI 是主动联系你的
- 关系是持续存在的
- 演示路径是可恢复的

推荐说法：

> 消息列表不是一个入口页而已，它是在证明这些 AI 角色并不是“点进去才存在”，而是在持续和用户发生联系。

## 聊天页

优先强调：

- 用户输入会改变关系
- AI 不是一次性回答机器
- 互动会推动后续人生发展

推荐说法：

> 这里展示的不是单轮问答，而是用户在一步步塑造这个 AI 的人生关系走向。

## 动态页

优先强调：

- AI 有聊天之外的生活痕迹
- 关系状态会溢出到聊天框之外
- 用户能感受到“它在过日子”

推荐说法：

> 动态页让角色从聊天对象变成生活主体，这也是“AI 好友活着”感最强的地方之一。

## 资料页 / 我的页

优先强调：

- 状态是可解释的
- 关系是可外显的
- 演示数据与恢复路径是有组织的

推荐说法：

> 资料页和我的页负责把这段关系解释清楚，让体验不是只有感受，也有可展示、可总结的结构化信息。

## 结局 / 时间线页

优先强调：

- 用户影响是可收束的
- 整个体验有终局和回看价值
- 产品从聊天升级成“人生剧本”

推荐说法：

> 结局和时间线证明了用户不是只参与了一段对话，而是参与了一个角色的人生。

## 5. 容易说空的话，建议这样改

### 不建议

- “这里我们做了一个动态页。”
- “这里加了一个资料页。”
- “这里支持搜索和筛选。”
- “这里有本地缓存。”

### 更建议

- “动态页是在证明角色聊天之外也在持续生活。”
- “资料页是在把关系变化外显化，方便用户理解这段关系走到了哪里。”
- “搜索和筛选是在缩短演示恢复路径，也让高频场景切换更稳定。”
- “本地缓存是在保证体验连续性，而不只是技术实现细节。”

## 6. 时间不够时的最小讲述顺序

如果只有 45~60 秒，可优先按这条顺序讲：

1. **主动消息**：证明 AI 会主动联系你
2. **关系推进**：证明用户输入会改变关系
3. **动态 / 空间流**：证明 AI 在聊天之外也在生活
4. **结局 / 时间线**：证明你影响的不只是当下回复，而是整个人生走向

可直接收束为：

> 我们想证明的不是 AI 会不会聊天，而是它能不能像一个会主动联系你、会被你影响、会持续生活的好友。

## 8. 一句话原则

在比赛冲刺阶段，最容易被忽略的不是功能数量，而是“每个功能到底在证明什么”；把功能、价值、证据和说法对齐，本身就是一次低风险但高收益的自动迭代。
