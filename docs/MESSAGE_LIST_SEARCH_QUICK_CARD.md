# LifeScript Message List Search Quick Card

用于在消息列表页快速决定“先搜什么、按什么键、先讲哪几个点最稳”的速讲卡。

这份卡适合以下场景：

- 你准备在消息列表页展示桌面端搜索效率
- 你想把“搜索角色 / 消息 / 标签、快捷视图、最近记录、快速恢复”讲得更集中
- 你需要在 20 秒、40 秒、60 秒三种时间盒里快速收束表达
- 你希望消息列表页的演示更像真实 IM 产品，而不是静态截图翻页

---

## 1. 这页最值得讲的 5 个点

如果时间有限，优先从下面 5 个点里选，不要试图一次把消息列表所有细节都讲完。

### 1. 桌面端可用 `/` 或 `⌘/Ctrl + K` 直接聚焦搜索

适合强调：

- 录屏或答辩时不需要手动把鼠标点到搜索框
- 更像真实桌面 IM 的高频操作
- 演示节奏更顺，也更容易体现产品完成度

### 2. 搜索不是只搜角色名，也能搜消息内容和标签

适合强调：

- 用户不只是在找“某个人”，也可能是在找“某种话题”
- 用“天气”“深圳”这类词更容易讲出画像、城市和关系上下文
- 消息列表不是死列表，而是带有可检索语义入口的会话总览

### 3. 系统会保留最近搜索，方便回到目标聊天

适合强调：

- 录屏中断或答辩切页后，能更快回到上一次讲述节奏
- 搜索过 2 个字以上的关键词后，会沉淀成最近记录
- 这类细节能说明产品在考虑真实演示与连续使用场景

### 4. 快捷标签和快捷视图能把列表快速收窄

适合强调：

- 可以直接点“主动 / 暧昧 / 天气 / 深圳”这类快捷标签
- 也可以切到“有未读 / 可继续 / 有草稿 / 关系升温 / 已固定 / 已静音”视图
- 再次点按当前标签或当前视图，会自动返回“全部”

### 5. `Enter` 与 `Escape` 让搜索闭环更完整

适合强调：

- 聚焦搜索框后，按 `Enter` 可直接打开首条命中聊天
- 按 `Escape` 可先清空搜索；若当前已空，再按会退出搜索焦点
- 这让消息列表的演示更像“真正在操作产品”，而不是只展示界面

---

## 2. 最稳妥的推荐展示顺序

如果你已经在消息列表页，建议按下面顺序讲，不容易乱。

### 最稳妥顺序

1. **先用 `/` 或 `⌘/Ctrl + K` 打开搜索**
   - 用一句话说明“这里支持桌面端快速检索，不用每次手点输入框”
2. **搜索一个容易讲价值的词**
   - 推荐优先搜：`天气`、`深圳`、`暧昧`
3. **指一下快捷标签或快捷视图**
   - 让听众看到它不仅能搜，还能快速切观察角度
4. **按 `Enter` 进入首条结果**
   - 顺势切到聊天页继续主链路
5. **需要收束时，再补一句最近记录 / 恢复能力**
   - 说明系统会尽量帮助下次快速回到目标会话

### 如果只剩十几秒

就保留这三步：

1. `/` 打开搜索
2. 搜“天气”或“深圳”
3. 说“按 Enter 就能直接进入首条结果，最近搜索也会保留下来方便继续演示”

## 3. 三档速讲版本

## 20 秒版本

> 消息列表不只是展示谁给我发过消息，它本身就是一个高效入口。桌面端可以直接用 `/` 或 `⌘/Ctrl + K` 聚焦搜索，支持按角色、消息内容和标签检索，再配合快捷视图快速收窄范围。这样录屏和答辩时能很快回到目标聊天，不用在列表里慢慢翻。

## 40 秒版本

> 这一页想强调的是“会话入口的效率”和“演示恢复能力”。桌面端可以直接用 `/` 或 `⌘/Ctrl + K` 聚焦搜索，像真实 IM 一样快速找人、找消息、找标签；比如搜“天气”或“深圳”，就能顺势讲到城市关怀和兴趣画像。除此之外，页面还有主动、暧昧、天气、深圳这类快捷标签，以及未读、可继续、有草稿、关系升温等快捷视图。按 `Enter` 可以直接进入首条结果，最近搜索也会自动保留，方便下次快速继续演示。

## 60 秒版本

> 消息列表在这个产品里不是简单的会话封面，而是整个演示链路的调度入口。我们给它补了桌面端快捷搜索能力，用户可以用 `/` 或 `⌘/Ctrl + K` 直接聚焦搜索框，不必每次重新点选；搜索对象也不只限于角色名，还包括消息内容、关系标签和推荐语义，所以像“天气”“深圳”“暧昧”这样的词都能快速找到对应聊天。为了让录屏和答辩更稳定，这里还提供快捷标签、快捷视图和最近搜索记录，帮助快速回到目标会话；而且按 `Enter` 可以直接打开首条结果，按 `Escape` 可以清空或退出搜索，让整个消息列表更像真实可用的产品，而不是演示专用静态页。

## 4. 推荐优先搜索词

如果你不想临场现想，优先从下面几类词里选：

### `天气`

适合讲：

- 城市化天气关怀
- 主动消息不是统一模板
- 搜索不仅找人，也能找话题

### `深圳`

适合讲：

- 城市上下文会影响表达
- 角色会结合用户场景组织消息
- 方便桥接到“画像 + 关系 + 情境”

### `暧昧`

适合讲：

- 关系阶段不是抽象概念
- 列表能快速回到更有戏剧张力的聊天入口
- 适合切到聊天页继续讲关系推进

### `主动`

适合讲：

- LifeScript 不是被动等你开口
- 列表页本身就能证明 AI 会主动联系你
- 方便桥接到推荐理由和会话恢复入口

## 5. 现场更适合强调的细节

如果页面状态合适，可以优先挑 1~2 个细节补充，不要全讲。

### 最近搜索记录

适合讲：

- 搜过的关键词会留在列表页里
- 下次答辩或继续录屏时更容易快速找回目标聊天
- 是“恢复演示节奏”的小但真实的产品细节

### 快捷视图

适合讲：

- 未读、可继续、有草稿、关系升温、已固定、已静音这些视图更适合讲“会话管理”
- 再次点按当前视图可回到全部，学习成本低
- 适合现场快速切出不同讲法

### 最近聊天优先 / 最近互动优先

适合讲：

- 列表不仅能搜，还会帮助把更适合继续讲的聊天排到前面
- 对录屏、彩排和多轮答辩都更友好
- 能体现这不是一次性演示界面，而是在考虑连续使用

### 搜索键盘闭环

适合讲：

- `/` 或 `⌘/Ctrl + K` 聚焦
- `Enter` 直达首条结果
- `Escape` 清空或退出
- 这三步足够在现场形成完整可讲的“效率操作闭环” 

---

## 6. 不建议动作

在消息列表页演示时，以下动作尽量避免：

- 一上来连续输入多个随机关键词，把节奏讲散
- 同时解释搜索、快捷视图、固定、静音、恢复、排序规则，信息过载
- 搜一个很抽象、现场难接话的词，结果自己也不好往下讲
- 明明已经命中目标聊天，还继续在列表里来回试不同条件
- 把重点讲成“搜索功能很多”，却没把它和演示恢复、关系推进主链路关联起来

---

## 7. 时间紧张时的保底策略

如果消息列表页状态一般，仍然可以保住核心表达。

### 最短保底动作

1. `/` 打开搜索
2. 搜“天气”或“深圳”
3. 指一下快捷视图
4. 按 `Enter` 进入首条结果

### 最短保底讲法

> 这一页的重点不是把联系人列表做得像 QQ，而是让演示者能快速找到最值得讲的会话入口。桌面端支持快捷搜索、最近记录和快速视图，所以可以很快从列表切到真正有价值的聊天场景。
