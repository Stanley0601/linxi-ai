# LifeScript Iteration Wrap-up Card

面向每轮自动迭代、手动补丁或低风险收尾后的“最后 3 分钟动作”速卡。

当 `npm run build` 与 `npm run lint` 已通过，但你还需要快速确认“这一轮到底算不算收稳了、接下来该怎么同步、哪些动作现在不应该做”时，优先看这份文档。

它特别适合比赛冲刺期、工作区较脏、多人协作或需要频繁通知执行结果的场景。

---

## 1. 适用场景

- 一轮自动迭代刚结束，想快速完成收尾闭环
- `build` / `lint` 已通过，但需要决定“现在该通知、记录、停下，还是继续扩改”
- 当前工作区已经较脏，不适合再顺手追加高风险改动
- 准备把本轮结果同步给协作者、评审者或另一个智能体
- 想降低“明明已经可交付，却因为继续顺手改而放大风险”的概率

---

## 2. 最后 3 分钟推荐顺序

建议严格按下面顺序做：

```text
看分支 → 看 git 状态 → 确认 build/lint 结果 → 判断本轮性质 → 记录 → 通知 → 停手
```

对应最小操作：

1. 确认仍在目标分支
2. 再看一次当前工作区是否已有较多未提交改动
3. 确认本轮验证是否至少覆盖 `build` 与 `lint`
4. 判断本轮属于：工程修复 / 体验优化 / 小功能增强 / 轻度重构 / 文档完善
5. 把结论写进迭代日志
6. 输出一条清晰通知
7. 如果没有明确的新低风险动作，就在此停下

---

## 3. 本轮结束前必须回答的 6 个问题

### 1）当前分支对吗？

至少确认自己还在目标分支，例如：

- `feat/v12-unified-baseline`

如果分支不对，本轮不要继续扩展修改。

### 2）当前工作区是不是已经很脏？

如果 `git status --short --branch` 已显示很多业务文件、样式文件、页面文件和文档文件一起变化，应默认进入保守收尾模式。

### 3）本轮改动有没有完成最基本验证？

最低建议：

- `npm run build`
- `npm run lint`

如果这两项都没过，不应把本轮描述为“已稳住”。

### 4）本轮改动是不是独立、低冲突、可解释？

优先满足：

- 能用一句话说明改了什么
- 风险边界明确
- 不依赖额外大改才能成立
- 不需要用户在多个方案间做权衡

### 5）现在继续改，会不会放大冲突面？

只要答案偏向“会”，就优先停止继续改代码，改为记录、通知、交接或手动复验。

### 6）现在最有价值的下一步是什么？

常见合理答案：

- 记录本轮结果
- 做一轮生产模式预演
- 准备录屏或答辩材料
- 同步给协作者
- 停止，等待下一轮

如果你给不出明确答案，默认停止继续扩改。

---

## 4. 推荐的收尾动作优先级

### 第一优先级：固定检查结果落地

优先沉淀：

- 当前分支
- git 状态结论
- 本轮目标
- 改动类型
- 验证结果
- 风险边界

### 第二优先级：形成可复用同步材料

优先输出：

- 一条通知
- 一条迭代日志
- 一张交接卡或补充说明

### 第三优先级：做额外复验而不是继续扩改

如果还想继续做点事，优先考虑：

- 生产模式预演
- 最小冒烟检查
- 文档索引补充
- 录屏/答辩辅助材料完善

而不是继续碰：

- 主状态机
- 共享类型
- 核心排序规则
- 状态恢复逻辑
- 大规模样式调整

---

## 5. 什么情况下应该立刻停下

出现任一情况就建议停止继续改动，并只做记录/通知：

- `build` 或 `lint` 失败，且原因还不明确
- 当前工作区已有较多未提交业务代码改动
- 新想法需要在多个方案之间权衡
- 继续修改会碰到主状态机、共享类型或跨页面联动逻辑
- 已经完成一项独立、低风险、可交付动作
- 你发现自己只是因为“还有时间”而想继续顺手改

## 6. 最短收尾模板

### 文字版

```markdown
- 分支：
- Git 状态概览：
- 本轮目标：
- 改动类型：
- 具体验证：build / lint
- 风险说明：
- 下一步建议：
```

### 一句话版

```text
本轮已完成固定检查与一项低风险独立交付，build/lint 通过，未扩大核心业务改动范围，建议记录后停止继续扩改。
```

---

## 7. 推荐通知结构

建议通知至少包含：

1. 本轮做了什么
2. 是否验证通过
3. 当前风险边界
4. 是否建议继续改

示例：

```markdown
【LifeScript 自动迭代完成】
- 分支：feat/v12-unified-baseline
- 本轮动作：补充一份独立收尾文档，帮助每轮结束后快速完成记录、通知与停手判断
- 验证结果：npm run build ✅ / npm run lint ✅
- 风险说明：未触碰核心业务逻辑，仅新增独立文档，冲突风险低
- 建议：当前工作区仍较脏，下一步优先做复验或交付准备，不建议继续扩大代码改动
```

## 9. 一句话原则

在 LifeScript 当前阶段，积极型自动迭代的最后一步，通常不是“再改一点”，而是把已经完成的低风险成果安全收住、说明白、同步清楚。
