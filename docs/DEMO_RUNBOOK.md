# LifeScript Demo Runbook

面向比赛演示、录屏、答辩前自检的快速操作手册。

## 适用场景

- 本地演示前快速确认项目可运行
- 录屏前检查推荐展示路径
- 答辩前准备讲解顺序与兜底说辞
- 提交代码前做一次最小风险工程自检

## 1. 演示前检查

### Git 工作区

先确认当前分支、未提交改动与是否存在高风险冲突：

```bash
git status --short --branch
git branch --show-current
```

建议优先在统一基线分支上继续演示与迭代：

- `feat/v12-unified-baseline`

如果当前工作区已经存在较多未提交改动，但 `npm run lint` 与 `npm run build` 仍然通过，优先继续做以下低风险动作：

- 补充独立文档或演示手册
- 完善录屏、自检、答辩相关说明
- 优化无争议的提示文案、空状态与可解释性表达
- 记录本轮检查结论，方便后续接手

这种情况下不建议为了“继续推进”而扩大到主状态机、共享类型或恢复逻辑等高冲突区域。

### 工程验证

至少执行以下命令：

```bash
npm run lint
npm run build
```

如果要做完整自检，再执行：

```bash
npm run verify
```

### 聊天接口兜底验证

如果本地配置了真实模型，建议额外确认一次异常兜底表现是否可接受：

- 当上游模型超时、返回空内容或短暂报错时，聊天接口应返回温和的 fallback 文案，而不是直接报错白屏
- 如果当前演示主要关注产品流程而不是模型质量，可不配置 `.env.local`，直接使用本地剧情引擎完成主线展示

## 2. 启动本地项目

```bash
npm install
npm run dev
```

默认访问：

```text
http://localhost:3000
```

### 录屏前快速恢复现场

如果你需要把现场状态快速恢复到一个“适合直接讲解”的样子，建议按下面顺序处理：

1. 先回到消息列表主视图
2. 清空搜索词与临时筛选
3. 检查是否有草稿、固定聊天、静音聊天等演示残留状态
4. 使用“继续上次演示”入口进入你准备好的角色会话
5. 再确认动态页筛选、资料页摘要与结局页是否仍符合本次讲解顺序

如果本地状态就是为了演示而保留的，不必强行重置；只要你能解释这是“为了快速恢复答辩现场”的设计即可。

## 3. 推荐演示顺序（3~5 分钟）

### A. 开场定位（15~20 秒）

建议先讲一句：

> LifeScript 不是“你问一句、AI 回一句”的工具，而是一个真的在 QQ 里活着、会主动联系你、会被你影响人生走向的 AI 好友。

### B. 消息列表（40~60 秒）

重点展示：

- QQ 风格消息列表
- 搜索角色 / 消息 / 标签
- 快捷视图：未读、可继续、有草稿、关系升温、已固定、已静音
- 最近继续演示入口
- 固定 / 静音 / 隐藏静音聊天

推荐操作：

1. 用 `/` 或 `⌘/Ctrl + K` 打开快速搜索
2. 搜索“天气”或“深圳”
3. 点按一个快捷视图
4. 展示“继续上次会话”卡片

### C. 聊天页（60~90 秒）

重点展示：

- 角色分条短消息回复
- 建议回复
- 兴趣画像影响对话内容
- 关系推进与阶段变化
- 未发送草稿 / 可恢复会话

推荐讲法：

> 用户不是一次性配置偏好，而是在聊天里不断塑造这个 AI 与自己的关系。

### D. 动态页 / 空间流（40~60 秒）

重点展示：

- 动态与关系状态联动
- 支持筛选更适合演示的内容
- 点赞、评论与本地记忆

推荐讲法：

> 它不只是会聊天，还会把“自己的生活”持续暴露在空间里，让用户感觉它真的在过日子。

### E. 资料页 / 我的页（30~40 秒）

重点展示：

- 角色资料与当前关系状态
- 本地演示数据摘要
- 最近继续演示入口
- 本地记忆如何帮助下次答辩快速恢复现场

### F. 结局 / 时间线（30~50 秒）

重点展示：

- 用户话语如何影响角色命运
- 不同角色拥有可收束的人生路径
- 这不是单轮聊天，而是持续推进的人生剧本

## 4. 推荐答辩话术

### 产品差异化

- 普通 AI：被动回应
- LifeScript：会主动联系、会发动态、会被关系影响

### 体验亮点

- “懂你”的主动开场
- 关系阶段：陌生 → 熟络 → 暧昧
- 城市化天气关怀
- 关系感知空间流
- 结局关系收束

### 工程亮点

- Next.js 16 + React 19 + TypeScript
- 本地状态持久化，便于恢复演示现场
- lint / typecheck / build 可验证
- 已有 CI，可用于 push / PR 基础验收
- 聊天接口在真实模型波动时支持安全回退，降低现场演示中断风险

## 5. 演示失败时的兜底顺序

如果现场时间紧或操作失误，建议按以下优先级保住主线：

1. 先展示消息列表 + 主动消息
2. 再进聊天页展示建议回复与关系推进
3. 然后展示动态页证明“角色在生活”
4. 最后补一个资料页或结局页收束

如果只能展示一个核心亮点，优先展示：

- **主动消息 + 关系推进**

因为它最能体现“AI 好友活着”的差异化。

- [ ] 已确认搜索、快捷视图、动态筛选可正常操作
- [ ] 已准备 15 秒产品定位话术
- [ ] 已准备 30 秒差异化总结

## 8. 备注

- 当前项目更适合本地演示与录屏，不依赖线上复杂环境即可完成核心体验展示。
- 若现场不方便接入真实模型，Mock 流程也能完整覆盖产品主线。
- 若浏览器保留了上次本地状态，可优先利用“继续上次演示”缩短现场操作路径。
- 若使用真实模型进行演示，建议提前验证网络稳定性；用户本地电脑若处于弱网环境，上游模型响应时间可能波动。
