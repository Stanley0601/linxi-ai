# LifeScript Smoke Test Matrix

面向比赛演示前、录屏前、提交前的最小人工冒烟验证矩阵。

当 `npm run build` 与 `npm run lint` 已通过，但你仍希望快速确认核心体验没有明显回退时，优先使用这份文档。

## 适用场景

- 刚完成一轮低风险自动迭代
- 工作区已经较脏，不适合继续扩大代码改动
- 准备录屏、答辩或本地彩排
- 想用 3~8 分钟快速确认核心展示链路仍可讲述

---

## 1. 使用原则

这份矩阵只关注：

- 核心页面是否可达
- 关键操作是否能完成
- 页面反馈是否符合预期
- 是否存在会直接打断演示的明显问题

它**不追求完整测试覆盖**，而是用于比赛冲刺阶段的“最小可讲述性验证”。

如果在验证过程中发现以下任一情况，应停止继续扩展自动迭代：

- 需要修改主状态机
- 需要联动多个共享类型
- 需要覆盖当前未提交业务改动
- 修复方案存在多种权衡，需要人工取舍

---

## 2. 开始前固定检查

先执行：

```bash
git status --short --branch
git branch --show-current
npm run build
npm run lint
```

建议先确认：

- 当前仍在 `feat/v12-unified-baseline`
- 工作区虽然较脏，但工程验证已通过
- 本轮若继续推进，应优先选择低冲突动作

---

## 3. 最小冒烟矩阵

建议按下面顺序验证。只要主链路可讲述，就满足大多数演示前检查需求。

| 模块 | 入口 | 关键操作 | 预期结果 | 失败时优先处理 |
| --- | --- | --- | --- | --- |
| 首页/落地页 | 打开 `http://localhost:3000` | 进入应用 | 页面正常渲染，无明显报错或白屏 | 启动失败、白屏、首屏阻塞 |
| 消息列表 | 默认主视图 | 查看列表、顶部搜索、快捷视图 | 列表可见，搜索与快捷视图可操作 | 无法进入主流程、筛选失效 |
| 继续演示入口 | 消息列表顶部或摘要区 | 点击“继续上次演示”或等价入口 | 能恢复到一个可讲述角色会话，或至少不会报错 | 入口失效、跳转异常 |
| 聊天页 | 从消息列表进入任一角色 | 查看历史消息、建议回复、输入区状态 | 聊天页面可正常打开，建议回复与输入区反馈正常 | 聊天页空白、关键控件缺失 |
| 动态页 / 空间流 | 底部导航进入动态页 | 切换筛选、浏览卡片 | 列表可见，筛选可切换，内容结构稳定 | 筛选混乱、页面明显错位 |
| 资料页 / 我的页 | 底部导航进入资料或我的 | 查看摘要信息、演示辅助信息 | 关键摘要可见，页面结构完整 | 摘要缺失、展示区域异常 |
| 结局页 / 时间线 | 从可达入口进入 | 浏览结果摘要或时间线信息 | 可打开并完成讲解收束 | 页面不可达、结构损坏 |

## 4. 推荐时间盒

### 3 分钟极简版

适合录屏前最后确认：

1. 打开首页
2. 查看消息列表
3. 进入一个角色聊天页
4. 切到动态页
5. 回到资料页或结局页做收束

### 5 分钟标准版

在极简版基础上补充：

- 搜索一次角色或关键词
- 切一次快捷视图
- 验证“继续上次演示”入口
- 查看一次“我的”页摘要

### 8 分钟稳妥版

在标准版基础上补充：

- 再验证一个不同角色
- 检查固定/静音/筛选等本地状态是否仍可解释
- 简单确认演示话术对应页面仍然一致

---

## 5. 失败分级

### P0：立即阻断演示

例如：

- 首屏白屏
- 主页面无法打开
- 聊天页无法进入
- 底部导航不可用

处理原则：

- 优先修复首个明确阻断问题
- 不要顺手扩大为结构重构
- 修复后立即重新执行 `npm run build`、`npm run lint`

### P1：明显影响讲解连贯性

例如：

- 快捷视图不可用
- 搜索结果异常
- “继续上次演示”入口不稳定
- 动态页筛选与预期不一致

处理原则：

- 只在修复范围明确、改动面小的前提下处理
- 如果需要跨多个核心文件联动，先暂停并重新评估

### P2：不影响主线但可后续优化

例如：

- 文案不够顺
- 空状态不够清楚
- 某些统计信息解释性一般
- 个别视觉细节不够统一

处理原则：

- 优先进入文档、文案或演示辅助层优化
- 不要为了 P2 问题去冒 P0/P1 级代码风险

## 6. 结果记录模板

可直接追加到 `docs/ITERATION_LOG.md` 或临时记录中：

```markdown
- 冒烟范围：首页 / 消息列表 / 聊天页 / 动态页 / 资料页 / 结局页
- 阻断问题：无 / 有（描述）
- 演示主链路：可讲述 / 部分可讲述 / 不可讲述
- 是否需要继续改代码：否 / 是（原因）
- 更适合的下一步：补文档 / 调文案 / 修低风险问题 / 暂停权衡
```

## 8. 一句话原则

在 LifeScript 当前阶段，`build` 与 `lint` 通过并不等于演示一定顺畅；而最稳妥的补充验证，不是继续扩大代码改动，而是用一份短路径、可复用的冒烟矩阵快速确认主链路仍然可讲述。
