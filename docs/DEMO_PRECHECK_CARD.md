# LifeScript Demo Precheck Card

面向比赛答辩、录屏开始前、临上场前最后 60 秒的极简检查卡。

当你已经确认工程基本可用，但只剩很短时间再看一眼“现场是否适合直接开讲”时，优先使用这份卡片。

---

## 适用场景

适合以下时刻快速对照：

- 已经完成 `npm run build` 与 `npm run lint`
- 准备开始录屏，但只想做最后一次极简确认
- 即将答辩上场，担心浏览器状态或讲解顺序临时混乱
- 当前工作区较脏，不适合再继续扩大代码改动

这份卡片**不替代**完整演示手册、恢复手册或冒烟矩阵，而是回答一个更具体的问题：

> 如果现场只剩 60 秒，我最应该确认哪几件事？

---

## 1. 60 秒检查顺序

建议严格按下面顺序看，不要临场想到什么查什么：

### 第 1 步：确认当前入口还可讲

只看三件事：

- 当前是否仍在 `feat/v12-unified-baseline`
- 本地页面是否能正常打开
- 现在停留的页面是否适合作为开场入口

如果不适合作为开场入口，优先回到：

- 消息列表主视图

因为它最容易重新组织讲解顺序。

### 第 2 步：清掉会打断讲解的显性状态

优先检查：

- 搜索词是否还残留
- 快捷筛选是否停留在局部视图
- 页面是否误停在深层聊天、资料或结局页

如果存在上述情况，优先把页面恢复到“可直接开讲”的主视图，而不是现场临时解释复杂上下文。

### 第 3 步：确认一条最短主链路

建议只保留一条最稳的路径：

1. 消息列表
2. 聊天页
3. 动态页或资料页
4. 结局页或一句收束总结

如果时间更紧，至少保住：

- **主动消息 + 聊天关系推进**

### 第 4 步：确认一句开场定位

建议提前固定一句最短开场：

> LifeScript 不是被动陪聊，而是一个会在 QQ 里主动联系你、被你影响人生走向的 AI 好友。

只要这句话还成立，现场主线通常就不会跑偏。

### 第 5 步：确认一个救场说法

如果页面状态和预想略有差异，优先使用这句解释：

> 这里保留的是本地关系与演示上下文，所以你看到的是一个被长期互动过的 AI 好友现场，而不是冷启动空白页。

这样能把“状态残留”转成“产品记忆感”。

---

## 2. 最短核对清单

上场前只看下面这 8 项即可：

- [ ] 当前分支正确
- [ ] `npm run build` 已通过
- [ ] `npm run lint` 已通过
- [ ] 本地页面可正常打开
- [ ] 当前入口页适合直接开讲
- [ ] 搜索词 / 筛选条件没有干扰主线
- [ ] 已确定先讲哪个角色或哪条会话
- [ ] 已准备一句开场定位和一句救场解释

---

## 3. 30 秒极限版

如果真的只剩半分钟，只检查下面四件事：

1. 页面能打开
2. 回到消息列表
3. 确认要点进哪个角色
4. 记住一句产品定位

此时不要再现场改代码、调结构、重置大量本地状态。

---

## 4. 不该在最后 60 秒做的事

以下动作越临近答辩越不建议做：

- 临时改核心业务代码
- 临时清空全部本地状态
- 临时替换演示顺序
- 临时扩展讲解范围
- 因为一个非阻断小问题重新组织整条演示路径

最后一分钟最重要的目标不是“变得更完美”，而是：

- **让主链路稳定、可讲、可收束**

比赛现场最后一分钟，优先确认可讲述性，而不是继续追求更多改动；只要主链路稳定、入口清楚、话术收束明确，这 60 秒检查本身就是高价值准备。
