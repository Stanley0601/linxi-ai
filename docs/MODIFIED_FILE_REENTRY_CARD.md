# LifeScript Modified File Re-entry Card

用于在 `build` 与 `lint` 已通过、但工作区已经较脏时，进一步回答一个更细的问题：

> 如果某个文件本来就已经有未提交改动，这一轮还能不能继续碰它？

它和现有文档的分工如下：

- `docs/LIFESCRIPT_SAFE_TOUCHPOINT_MAP.md`：回答“如果要落到文件，优先看哪里、默认别碰哪里”
- `docs/SAFE_SINGLE_FILE_UI_ENHANCEMENTS.md`：回答“如果继续改代码，哪些单文件 UI 微增强更安全”
- `docs/WORKSPACE_DIRTY_ITERATION_PLAYBOOK.md`：回答“工作区较脏时，这一轮整体还能安全做什么”
- **本文**：回答“当目标文件本身已经有未提交改动时，是否还能再次进入、进入到哪一层、什么信号一出现就该停”

一句话目标：

> 当工作区较脏、而你又准备继续碰一个“已经被改过”的文件时，帮助你先判断这是不是低风险的继续推进，而不是把单文件增强做成高冲突回合。

---

## 1. 什么时候优先看这张卡

适合以下场景：

- 已执行 `git status --short --branch`
- 已确认当前分支符合预期
- 已执行 `npm run build`
- 已执行 `npm run lint`
- 当前没有必须先修复的明确工程报错
- 你已经选中了一个相对安全的文件，但发现它**本轮之前就已经处于修改状态**

如果当前 `build` 或 `lint` 还未通过，先看 `docs/ITERATION_VERIFICATION_TRIAGE_CARD.md`；如果你还没决定应该选哪个文件，先看 `docs/LIFESCRIPT_SAFE_TOUCHPOINT_MAP.md`。

---

## 2. 先回答的核心问题

继续碰一个已修改文件之前，至少先回答这三个问题。

### 问题一：这个文件为什么已经被改过？

先快速判断：

- 这是上一轮明确留下的说明性增强吗？
- 这是用户正在进行中的业务改动吗？
- 这是你自己也说不清边界的混合修改吗？

如果你无法在 30 秒内说清它当前改动的大致意图，默认不要继续进入。

### 问题二：这次新改动和已有改动是“同一层”还是“跨层”？

**可继续进入**的典型情况：

- 都属于说明性增强
- 都属于提示语 / 空态 / aria 补充
- 都限制在同一文件、同一局部区域
- 新改动不需要推翻旧改动才能成立

**默认暂停**的典型情况：

- 已有改动是业务逻辑，这次却想顺手补结构性调整
- 已有改动是局部 UI，这次却需要补共享类型或状态字段
- 为了完成这次改动，需要回头重新理解整份文件当前的未提交修改

### 问题三：这次进入是否会放大“解释成本”？

如果改完后你很难一句话解释：

- 这次究竟新增了什么
- 它和这个文件里已有未提交改动是什么关系
- 为什么这仍然属于低风险

那通常说明这次 re-entry 已经不够稳。

---

## 3. 可以继续进入的 4 个低风险信号

命中越多，越适合继续。

### 1. 文件本身属于相对安全触点

例如：

- `docs/`
- `README.md`（仅限索引或说明性补充）
- `src/components/MessageListPage.tsx`
- `src/components/ChatView.tsx`
- `src/components/MomentsFeed.tsx`
- `src/components/MyProfileTab.tsx`
- `src/components/EndingView.tsx`
- `src/components/TimelineView.tsx`

前提仍然是：只做说明性、提示语、空态、辅助说明、aria 或轻量展示增强。

### 2. 新旧改动属于同一风险层级

例如：

- 已有改动是演示说明增强，这次还是补演示说明增强
- 已有改动是空态文案优化，这次还是补同页提示语
- 已有改动是文档索引补充，这次还是补一条低风险入口

一句话判断：

> 低风险 re-entry 更像“在已知边界内补齐一小块”，而不是“借着同一个文件继续扩大战线”。

### 3. 改动边界仍然能限制在局部

例如：

- 只补一个说明卡片
- 只补一段提示语
- 只补一个 aria label
- 只在索引区增加一条文档入口

如果进入后很快需要同时改多个区域，说明这一轮应该停。

### 4. 最小复验路径清楚

至少应该能明确：

- 改完后要检查哪个页面或哪段文档
- `npm run build` 和 `npm run lint` 仍然会执行
- 本轮日志里能一句话说明收益与边界

---

## 4. 默认不要继续进入的 6 个信号

命中任一条，都更适合停下说明。

### 1. 该文件已有改动的意图说不清

如果你只知道“它改过了”，却说不清“为什么改、改到哪一层、哪些区域不该继续碰”，不要继续。

### 2. 这次进入会把说明性增强升级成结构性改动

例如：

- 从补文案升级到改状态流
- 从补展示升级到改数据结构
- 从补索引升级到重排整份文档结构

### 3. 开始依赖其它文件一起改

如果进入一个已修改文件后，又发现：

- 还要同步改共享类型
- 还要同步改另一个组件
- 还要调整持久化或恢复逻辑

那它已经不再是低风险单点继续进入。

### 4. 你需要先理解大量旧 diff 才敢动手

如果继续修改之前，必须先花很多时间搞清已有未提交改动，否则不敢下手，说明当前回合不适合自动继续推进。

### 5. 你开始依赖“顺手一起改”来证明价值

常见危险信号：

- “既然已经改到这里，不如把这块也一起整理掉”
- “这个文件本来就脏，再多改一点也没关系”
- “顺便把结构也统一一下”

这些都不是低风险信号。

### 6. 改完后很难区分“这轮新增了什么”

如果最终通知或日志里无法把本轮增量单独讲清楚，就说明本轮边界不够干净。

---

## 5. LifeScript 当前更适合 re-entry 的场景

### A. `docs/` 中继续补一份独立文档

适合原因：

- 低冲突
- 收益容易解释
- 不会误伤核心业务逻辑
- 即使工作区很脏，也通常还能形成独立交付

最常见动作：

- 新增一份速卡 / 手册 / 协议
- 在 `docs/DOCS_INDEX.md` 中补入口
- 在 `README.md` 中补一条相关文档说明
- 在 `docs/ITERATION_LOG.md` 中追加本轮记录

### B. 单文件说明性增强再次进入

例如继续碰：

- `src/components/MomentsFeed.tsx`
- `src/components/MyProfileTab.tsx`
- `src/components/MessageListPage.tsx`

前提：

- 本轮只补说明性增强
- 不改排序、恢复、持久化或共享类型
- 不需要跨文件联动

### C. README / 文档索引的小范围补充

适合原因：

- 属于已有文档资产的自然配套动作
- 目标单一
- 易于解释与复验

默认别做：

- 重写 README 叙事
- 批量重排文档顺序
- 借机统一所有历史文案风格

## 6. 30 秒判断法

可直接按下面顺序快速判断：

```text
这个文件已经改过了吗？
  否 → 按正常低风险流程判断
  是 → 我能说清它为什么被改过吗？
        否 → 停下说明
        是 → 这次新改动和旧改动属于同一风险层吗？
              否 → 停下说明
              是 → 能限制在局部且不联动其它文件吗？
                    否 → 停下说明
                    是 → 可以继续做最小增量
```

一句话原则：

> 已修改文件不是绝对不能再碰；真正决定能不能继续的，是你能否把“已有改动意图、这次增量边界、复验路径”同时讲清楚。

## 7. 推荐记录模板

### 模板 A：允许继续进入

- 本轮继续进入 `{{file}}`，原因是该文件虽已有未提交改动，但当前新增内容仍限制在 {{提示语 / 空态 / 说明卡 / 文档索引}} 层；未扩展到共享类型、恢复逻辑、持久化结构或多文件联动。

### 模板 B：决定暂停

- 本轮未继续进入 `{{file}}`，因为该文件现有未提交改动边界不够清晰；继续推进需要先理解旧改动或联动其它文件，已超出低风险自动迭代边界。

### 模板 C：结果通知里的风险说明

- 本轮目标文件虽然已有未提交修改，但新增动作仍限制在局部说明性增强范围；未放大为结构性调整，复验路径清楚，整体风险可控。

---

## 8. 必须停下并说明的时刻

命中任一条就该停：

- 你需要先判断已有改动到底该保留还是回滚
- 你发现继续进入后必须再改第二个核心文件
- 你开始碰共享类型、恢复逻辑、持久化结构、API 核心行为
- 你发现这个文件虽然“看起来只是 UI”，实际上牵一发而动全身
- 你已经无法把本轮新增内容和旧改动清晰分开

---

## 9. 一句话结论

在积极型自动迭代里，**已修改文件可以继续进入，但只能在“旧改动意图清楚、新增边界局部、复验路径明确”这三个条件同时成立时继续**；否则，最专业的动作不是硬改，而是停下说明为什么这轮不该再碰它。
